## Implemented foundation

- Cold, source-only API-worker transport: captured source bytes, qualified
  function-entry accounting, bounded pipes and durable acknowledgements.
- A serial controller with paired preparation, canonical cohort references,
  stage ordering, saved export/projection binding, and a hash-chained ledger.
- Native Linux outer supervision, process-group cleanup, inherited resource
  limits, one-CPU affinity and an absolute 850-second kernel expiry.
- Saved-JSON evidence reconstruction and exact-rational scoring. The completed
  software fixture only verified its evidence and lifecycle; it produced no
  usefulness score or scientific classification.
- A prospective fixed registry for 32 pairs / 64 arm cases / 128 decisions,
  with explicit null accounting and reservations. Authored schedule tests do not
  constitute scientific samples or an executed full-study transport.

The portable read-only capture function is
`ora_study.freeze.capture_execution_root(api_root, study_root)`, where `api_root`
is the repository root and `study_root` is the `executed_snapshot/` directory.
It verifies the original numerical/runtime pins and returns NO-GO. The older
`capture(workspace_root)` expects historical investigation directories and is
not the repository entry point. Publication does not refresh runtime fingerprints
or transfer approval to a new path, build or machine.

## Known unadmitted scientific-scoring issue

The frozen scientific scorer has a known incomplete-run ordering-classification defect: a second owned outcome can exist without a committed common F set and be classified incomplete instead of invalid. The scientific scorer and driver are unadmitted. Correction and verification belong to the separate scientific extension; the completed software fixture performed no scientific scoring and remains valid.

This publication preserves the executed source exactly; it does not repair or
approve the scientific scaffold.
