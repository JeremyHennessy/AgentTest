# One predeclared comparison: using the outcome of an owned investigation

Proposal v3, 2026-10-07. Status: unimplemented, unrun. This document does not
authorize an experiment or extend #222's existing capsule profiles.

## Question and scope

Does retaining the actual outcome of an internally selected and owned test
improve the new policy's next position predictions and change its next bounded
test, from an otherwise identical public state and inquiry lifecycle?

Both arms use every common mechanism in `POLICY_AND_API.md`. The contrast is
retaining versus withholding **one first owned action's evidence** at the second
selection, not new policy versus old Core. Generation, admission, model class,
selection algorithm, context, prior public evidence and budgets are held fixed.
This isolates the causal contribution of that evidence to a frozen algorithm;
it does not isolate the separate merits of generation and action selection.

This is a two-decision micro-loop in fresh synthetic copies of the unchanged
Challenge world. The first action really is internally chosen, durably consumed
and interpreted before the second decision. The harness does not prescribe a
route, target result, return or successful first action. A move may change public
context so its evidence is not locally applicable to the next decision. That
honest zero-effect result remains in the study. The first action can also be null.

The neutral prefix below is common setup. It is not counted as policy-owned
investigation, autonomous learning or a natural-input trial. A positive result
would establish bounded own-outcome predictive use under this intervention, not
open-ended self-directed learning, multi-owner resumption or transfer.

## Corpus and prospective freeze

Use existing `initial_world` layouts 1, 2, 3, 4, once each. Higher seeds do not
create extra independent worlds: these four are mirrored layouts. Retain that
limitation; no iid standard errors or broad significance claims.

For each layout, generate exactly 64 neutral transitions with the unchanged
`choose_command(observation, attempt_counts)` and `candidate_commands`. Counters
start empty. This existing public explorer can use all existing action kinds;
the tested policy can use only the four movement commands. For every actual
neutral attempt, including a blocked/unsuccessful one, increment exactly once
its pre-action key `(observation_signature(before_observation), command_key(command))`
after that actual transition. `choose_command` does not increment it itself.
No branch, owned action or evaluator probe touches these neutral counters.
The least-tried tie rule provides setup coverage, not a solution route or the
candidate's reward.

- D = initial observation and transitions 1–32. Generate and freeze the common
  explanatory cohort from D exactly once per layout.
- Anchors are after neutral t = 32, 36, 40, 44, 48, 52, 56, 60: eight per layout,
  32 total. No replacement, extension, favorable start or resampling.
- U = neutral transitions 33 through t, supplied identically to both arms as
  pre-existing public evidence. The initial context C0 is the observation at t.
- All subsequent branch outcomes are excluded from the neutral stream. The
  neutral command schedule/counters cannot inspect either policy or its outcome.

Freeze the generator, policy, masks, neutral schedule, dependencies, derivation
language, numerical conventions, scorer, thresholds, resources and reporter
before producing any new stream. D then becomes declared construction data;
U is common online evidence. First and second branch outcomes remain withheld
from both policies until the proper durable action stage. Evaluator probes are
never policy inputs.

This is not a novel-mechanics or unseen-context benchmark. Existing source and
negative studies informed the design, and some contexts may match old ones.
Do not label it disjoint from #218/#219, replay their histories to build a split,
or revise their results. All new branch outcomes are prospective, not selected
after inspection. They are “held out” from design and pre-action forecasts in
that precise temporal sense, not from all prior knowledge of the world.

## Exact paired micro-loop and intervention

At each anchor create two fresh capsules through the ordinary explicit-create
path from byte-identical logical inputs copied into two separate source-file
sets. Never copy or edit a sealed capsule to change its run/path, invoke an
unimplemented fork/migration, or reset either capsule's counters. The two cases
are declared in the global budget before creation. Run/path IDs are provenance
only and cannot enter policy calculations. Compare semantic public-state/menu/
forecast/selection digests with those provenance fields explicitly separated;
verify full per-run identity normally at the authority boundary.

The capsules have identical copied world, initial copied
Ora state, complete verified public prefix, model cohort and budgets. Both use
`grounded_policy_v2` and start from a fresh interpreter boundary. Give both the
same D, U, current C0 and initial uniform model weights updated by the same
unique exact-context/action U records. There is no intervention yet.

1. Internally generate/admit identical bounded context-local inquiry menus from
   D and C0. Both policies select once. Before either world effect, commit each
   complete T1 receipt and every movement forecast. The two choices, forecasts
   and receipt bodies must be equal up to run-local IDs. A difference is invalid.
2. Restart both. Execute their identical selected command once, if non-null.
   Persist complete actual outcomes E1R/E1W. Verify public outcomes equal. Restart
   again and complete T3 from each saved result. Both have the same actual current
   context C1, completed counts, inquiry statuses, interpretation status, time
   schedule and remaining budget. There is no forced cancellation or resumption.
3. Retain full history in both authoritative capsules. For the **second policy
   intake only**, R receives the actual first owned transition E1; W receives an
   outcome-free placeholder for that transition. Both retain identical D, U and
   current C1. W does not receive the first branch's pre-context, action,
   receipt/after-frame, selected-owner/forecast history, evidence-bearing belief,
   derived counts or posterior cache through a different policy input. Common
   lifecycle metadata says an owned attempt completed and was interpreted, but
   does not expose its payload. Every source and ownership check still uses full
   actual history inside the separate authority boundary.
4. Recompute model weights through the same declared updater from common U plus
   the arm's visible E1. R may use E1 only if E1's pre-context exactly equals C1
   and its action matches the evaluated action. If the move changes context, that
   event supplies no local update at C1. W has no E1 likelihood update. Never
   mask U in one arm or seed W with R's updated weights.
5. Internally generate the second current-context case menu and select once;
   freeze/commit full T1 forecasts before any second action. Execute the selected
   owned command or truthful null; restart and complete T3. No available runner-up,
   previous owner, return action or other arm's choice substitutes for the winner.

If step 1 is null, E1 is absent and both still make their second budgeted decision
with identical evidence. Their outputs must again agree. Nulls cost decisions,
not actions; no extra attempt fills the slot.

Each generated case has one immutable concrete hypothesis set. The second case
may use the same C or a new C; it is separately named and grounded, not a claimed
meaning migration, successor or resumption. Both arms create the same cases and
statuses before the evidence contrast. T3 history remains durable, but no old
hypothesis definition is edited. This requires the separately reviewed v2
admission seam; it is not supported by #222 unchanged.

### What the mask can and cannot establish

The common generator sees D/current C only, never E1 or U when constructing rules.
The updater alone sees eligible evidence. The authority capsule holds every real
record, but the selector receives only a materialized allowlisted JSON view in a
separate interface. Recorder counts, legacy summaries, cached weights, outcome
paths and evidence-bearing first-decision histories cannot bypass the mask.
Freeze and independently audit both exact view schemas and their reachable code.

Current C1 is intentionally identical and visible to both arms. It may indirectly
reveal what occurred, and common D/U plus the deterministic policy may let an
observer infer a past action. Do not claim W has no possible knowledge of E1;
the intervention removes the explicit retained event and its derived updates
from this specified policy. The updater's only outcome ingestion is validated
transition rows, not an unreviewed reconstruction channel. This conservative
information overlap can reduce the observed effect and cannot be “fixed” after
unblinding by hiding the current observation or changing control lifecycle.

The forecastable context/action set and rule cohort are identical between arms;
only likelihood weights differ. Source checks do not accept fake/missing history
because one policy view is intentionally masked. Full canonical mask receipts
bind included/excluded record hashes, reason, exact projection and prior-state
hash; they are generated by the trusted evidence-view component, not the policy.

## Common realized-outcome scoring outside candidate authority

After both second-stage T1 receipts commit, the independent evaluator makes four
disposable clones of their identical post-first-action world, then executes
north/east/south/west once each with the unchanged pure transition. If the first
choice was null this is the original anchor world. These are evaluator probes,
not policy-owned actions or extra scientific samples. No outcome preview happens
before selection. Their results never enter D, U, E1 or either policy.

Hash each actual command, receipt and observation. The neutral world and arm
worlds stay unchanged by probes. The policies/generator have no write authority
over the frozen scorer, log, probe source or report predicates. A distinct
evaluator process/interface supplies only declared public inputs to policy code:
no private-world object, callback, layout ID, transition function or evaluator
path. Freeze the complete reachable source manifest and independently review the
actual boundaries. These are trusted-process/source-integrity guarantees, not
hostile-OS sandboxing or cryptographic source authentication.

Score realized public receipt/observation outcomes only. Each action a has three
outcome classes: zero displacement, its D-inferred nonzero displacement d, other.
Receipt before/after must match the public frames. Position is always present in
this sensor; unexpected absence is an integrity failure, not a dropped bad result.
No hidden entity kind, expected target state or receipt-success reward is used.

Each arm's second owned outcome must exactly match that command's independent
probe outcome from the same world. An identical result is not counted twice.
Score equal commands against common outcomes, so changed choices cannot hide
hard predictions. The first owned action's frozen forecast/outcome is also
reported, but is not an extra primary comparison.

## Endpoints and all denominators

At second-stage anchor i, F_i is the common set of movement commands with a valid
frozen cohort/forecast in both arms, even if concrete predictions agree and the
command cannot own a distinguishing inquiry. Determine F_i from D/current C1
before probes. No exclusion depends on success, blocked status, correctness or
what the scorer later observes. Empty F_i gives unavailable loss, never zero.
Missing/overflowed cohorts remain coverage failures in the report.

For three-class probability p and actual class y, loss is
`0.5 * sum_k (p_k - indicator(k == y))^2`, in [0,1]. Average over F_i per anchor.
Retain each probability vector, actual receipt and per-action score.

Group anchors by exact C1 modulo four coordinate sign-flip mirrors: consistently
transform public agent/entity positions and take the minimum canonical context
serialization. Do not transform IDs or public states. This is evaluator-only,
never a policy feature. Average anchors within each group, then weight groups
equally. Report also micro and four layout means. This finite-corpus context
balance cannot turn mirrored layouts into independent samples.

Primary B = loss(W) - loss(R) on the identical F. Positive means the explicitly
retained owned outcome improves prospective prediction. Ownership, rule counts,
receipts, cycles, belief versions, entropy reduction and posterior confidence
cannot add to B. They are not substitutes for a proper predictive score.

Report separately:

- Prediction: B, both losses, every denominator, per-context/layout values, number
  of local U/E1 rows, unresolved-model N mass, and “other” outcomes.
- Choice: every first and second owner/command/null, differences at the second
  decision, all I scores, and whether an R second action's actual outcome matches
  at least one concrete prediction and contradicts another. A changed decision
  can be worse; differences alone are not benefit.
- Costs: both-stage decisions, owned attempted actions, blocked moves, nulls,
  evaluator probes, CPU/wall time and persisted bytes. Better prediction does not
  automatically establish more efficient exploration.
- Formation/limits: source-grounded programs, generated/retained counts,
  generator overflow, absent/distinguishing cohorts, and label/dedup controls.
- Causal chain: first T1 -> persisted E1 -> canonical T3 -> second view/mask ->
  weights/forecasts -> second selected owner -> actual second outcome. Preserve
  all alternative same/no-change paths, including the first-null cases.

## Predeclared pass/fail/inconclusive rules

Sufficient coverage requires all:

- At least 16 second-stage anchors with two or more commands in F, spanning all
  four layouts and at least four mirror-normalized C1 groups.
- At least eight of those anchors have an actual first owned transition whose
  pre-context equals C1 and whose action belongs to F, spanning two context
  groups and two layouts. This criterion is assessed from already-realized E1
  before any second outcome, but is only a coverage report, never an inclusion
  filter: changed-context and non-local cases remain in primary scoring.
- A complete four-command forecast-or-unavailable record and valid ownership/null
  receipt for every one of the 64 scheduled arm cases at both stages. Each command
  in F must have its full forecast; each other command must have its frozen
  absent/invalid-cohort reason. F-empty records are legitimate coverage failures,
  not missing data. An omitted required row/prediction is an integrity failure. All first-stage arms are exactly equal up
  to identities; every first-null pair remains equal at stage 2.

A **finite-corpus own-outcome predictive benefit with evidence-sensitive test
selection** requires sufficient
coverage, B >= 0.05, and:

- No layout's mean R loss exceeds W by more than 0.025 on its identical F.
- At least four second-stage choice differences spanning two context groups;
  at least four of these difference anchors have an R-owned second action whose
  actual outcome distinguishes two concrete predictions as defined above.
  These are behavioral adequacy checks, not independent scientific samples.
- Every integrity, source, lifecycle, masking and budget gate holds.

The 0.05/0.025 thresholds are prospective practical decision limits, not powered
effect estimates or values derived from #218. A single extra retained outcome
may be insufficient. That is an informative narrow negative/inconclusive result;
do not add trials or choose only blocked first actions to manufacture coverage.

Classification order:

1. Authority/source/leakage/integrity failure: **invalid**; stop, retain partial
   artifacts. This is not evidence against the learning hypothesis.
2. Resource interruption: **incomplete**, exact counts preserved. No blind reset;
   exact-once resumption needs an audited continuation decision.
3. A breached evaluable per-layout 0.025 guard: **adverse observed prediction
   result**, even if other coverage is insufficient.
4. Insufficient coverage or a required unavailable denominator: **inconclusive**.
5. Adequate coverage/no regression but B < 0.05: **no demonstrated useful
   prediction benefit**, including a null. Choice differences do not rescue it.
6. B >= 0.05 but insufficient behavioral adequacy: **own-outcome predictive
   benefit only; evidence-sensitive selection unestablished**, not the full pass.
7. Every predicate: **finite-corpus own-outcome predictive benefit with
   evidence-sensitive test selection**.

Changed choices plus discrimination do not prove better action utility: the
changed action may be worse. Comparative realized action benefit and efficient
exploration remain unestablished. This first score is deliberately same-context
predictive retention, and may include predicting a repeat of the first blocked
command in a deterministic world. It is not held-out-context generalization or
new causal-mechanism discovery.

Keep unfavorable outcomes and every denominator. No pass establishes causal
world laws, calibrated general learning, model/representation evolution, robust
noise avoidance, sustainable persistence, transfer, actual two-owner resumption,
open-ended discovery, new-world readiness or live activation.

## Exact ceiling and stopping condition

This is a proposed reviewed study profile, not resets of an exhausted #222 run.
Register all 64 arm-case IDs and the global budget before execution. Each arm
case has two decisions and at most two owned actions on its single copied branch.
It never returns into the neutral trajectory or continues with reset counters.

- Neutral transitions: exactly 4 x 64 = 256.
- Policy decisions: exactly 32 anchors x 2 arms x 2 stages = 128, including nulls.
- Policy-owned transitions: at most 128; blocked still consumes one.
- Common-outcome evaluator probes: exactly 32 x 4 = 128.
- Maximum new simulator transitions: **512**.
- Model construction: four D cohorts, once each; at most 128 conditional source
  candidates per action, seven concrete retained rules plus N. No generation
  from U or E1; no changes to the cohort after D is frozen.
- Each arm capsule: 2 MiB maximum canonical bytes, two decisions, at most two
  actions. The new envelope's completion bound must be proved before execution.
  If inadequate, revise/review before running; do not enlarge a running profile.
- Whole study: 192 MiB new durable output, 512 MiB process RSS, 15 CPU minutes,
  25 wall minutes. Hard safeguards, not measured runtime promises.
- Core cycles, old-prefix reconstruction, historical-organism runs, #218 reruns,
  #219 held-out runs, real-world actions, provider calls and spending: zero.

These are whole-run limits, enforced by one frozen independent run controller,
not per-phase resource snapshots. The accounting window starts before initial
source validation/process startup and ends only after final report/lock/seal
writes and finalization. Include all source checking, input materialization,
neutral setup, owned actions, evaluator probes, restarts, capsule validation,
report generation, temporary replacements, logs, locks, sealing and cleanup.
Aggregate CPU across the controller and its descendants; wall time is one
monotonic window; peak RSS is the concurrent process-tree total. The output cap
covers every new run-owned byte, including source-input copies, authoritative
capsules, raw records, temporary files and final reports. Existing immutable
read-only source inputs are not new output. No counter restarts between phases.

Reserve 1 MiB of the 192 MiB output ceiling for controller status/failure records
and finalization; scientific artifacts cannot borrow that space. Maintain the
independent ledger from before startup, with every scheduled, started and durably
completed decision/transition classified by neutral/owned/probe stage. Reconcile
owned counts against authoritative committed outcomes, including lost responses,
before reporting; never count a recomputed uncommitted pure transition as another
durable action. Also report actual transition function invocations separately
where a crash caused recomputation. Every invocation consumes the global simulator
ceiling: crash retries do not silently increase the declared 512 calls.

Startup, source-validation, restart, reporting, locking and sealing failures use
the same structured terminal result as mid-run failures, with phase, reason,
last validated state and exact completed/attempted counts. Integrity/source
failures are invalid; interrupted startup/finalization is incomplete unless it
also establishes an integrity failure. A run is not complete merely because the
last probe executed. If an evidence loss makes a count unverifiable, mark that
specific count unknown and the result invalid rather than inventing a number;
retain all independently verified ledger counts. No late error permits a reset,
new output directory, unlocked rerun or substitution of a self-reported phase
summary. The controller/failure-path design is part of independent pre-execution
review, including a usable reserved failure report before the first startup.

No scientific replay allowance is implicit. Report generation reads saved
outcomes only. API/unit checks before freeze can use separately reviewed
synthetic policy/transaction fixtures; this document does not authorize extra
world transitions for developing them. Keep software-test and scientific counts
separate. No source imports or tests were run to prepare this proposal.

Stop after the fixed slots/neutral horizons, or immediately on a fail-closed
condition. Null/adverse/inconclusive is terminal for this protocol. No tuning of
noise assumptions, context granularity, capacity, rule ordering, thresholds or
schedules after outcomes. A report bug may be corrected from unchanged artifacts
with separately hashed code and disclosure; it cannot change the scientific rule.

2. Separately reviewed API/policy implementation and invariant suite, preserving
   frozen v1 reopening and all prior negative controls.
3. Independent pre-execution review of both evidence views, masking, cohort,

   Generated D/U/E1 cannot be pre-hashed before existence: commit their raw event
   hashes before any dependent selection. Include exact skip and completion rules.
4. Execute once only after that gate. Seal effectiveness metrics while allowing
   resource/integrity observation. Seal full records before unblinding.
5. Deliver one compact result JSON and report: manifests, both-stage public
   views, model derivations, receipts, outcomes/probes, scores, all costs,
   exclusions/nulls and terminal classification. No new archive-packaging project.

The immediate implementation step is the reviewed admission/receipt seam and its
invariants. The subsequent scientific step is this single own-outcome contrast.
Neither reopens legacy score tuning or archived benchmark quotas.
