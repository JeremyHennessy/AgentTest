## Native resource entry

The statically linked native outer has no required live Python helper. It arms an
absolute kernel BOOTTIME expiry using process birth, before startup validation,
and keeps it armed through terminal writes and exit. It pins the entire tree to
one already allowed CPU before fork. A prospectively fixed 850-second internal
window keeps aggregate scheduled tree CPU below the unchanged 900-second cap and
within the unchanged 1,500-second wall ceiling under ordinary trusted Linux
semantics. It is not a hardware real-time promise or a claim about a failed kernel.

Soft AS limits are 32 MiB outer + 96 MiB controller + 384 MiB sole sequential
child = 512 MiB. Supervisors retain enough hard allowance for child inheritance;
their audited source does not raise its own soft bound. Child/report/reconcile
roles share one slot. Group termination, parent-death startup races, CPU/memory
refusal, bounded pipes and deadline expiry during blocked finalization have
explicit authored-stub checks. There are no credential/environment passthroughs.

The integrated authored Python controller uses the real source-only bootstrap
under 96 MiB, exercises 128 null schedule slots without scientific data, and
starts one fixed 384 MiB arithmetic child. Bad source digests stop it before that
child. The actual capped API controller/transport and its output bindings require
the separate exact-source fixture gate before use.

signoff, original design/review, and API loaded-source snapshot. See
`EXECUTION_ROOT.md` for portable roots; local investigation paths are developer
provenance only. Captured code/runtime/source manifests must be frozen together.
Changing machines/numeric runtimes requires prospective review, not automatic
fingerprint replacement. API bytes and old evidence are never rewritten.

The remaining gates are finite: capped actual Python process transport and all
output reservations; native authority/ledger-to-saved-scorer binding; exact-source
independent review; the separately approved six-call software fixture; then
publication/remote verification and an explicit scientific execution instruction.
Null/adverse/inconclusive is terminal. No run establishes action utility,
generalization, representation evolution or live activation.
